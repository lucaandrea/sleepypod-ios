The native screen opens only from an available supported processed parent. Every frozen night needs 1–64 distinct inspected archive identities; the search includes five minutes of pre-roll. Night selection keeps previous choices across pages, rejects nonoverlapping/unavailable/inconsistent inventory, and does not infer continuous coverage. Later night reads supersede older replies. Inspection details expose recorded event bounds, channel samples, lost markers, truncated bytes and timestamp/count limitations.

Archive scanning is explicit and requires a fresh admitted resource decision. GET admission refreshes in foreground; a failed or stale read cannot enable inspection. POST scan sends required `afterName:null` initially, then the exact returned filename cursor. Inspected/unavailable results must advance, deferred responses preserve cursor/selection, and completion does not imply waveform retention. Source names are displayed as text, never treated as phone paths.

A separate review retains the exact parent UUID/hash, every cohort/source identity and retry key in the existing protected controller/side store before POST. Deferred and unknown outcomes keep that request; reopening never writes. Published results must match the parent, side and cohort identities. Already-released results remain released. Retaining waveform inputs does not queue an evaluation or change a profile. Processed and waveform receipts are kept distinct so navigation back to the first review cannot open the wrong dataset.

The demo uses twelve linked parent/waveform fixture pairs generated by Core in an isolated in-memory SQLite database. Core validates synthetic catalog metadata and prepares canonical manifests/hashes. No archive files are read, copied or verified. The UI explicitly identifies synthetic metadata; these examples do not establish physical storage or replay readiness. Parent IDs remain exact because they are bound into waveform hashes. A second new-key duplicate of a bundled synthetic selection is rejected rather than changing that identity.

Focused checks cover Core fixture semantics, every-night selection, inspection counts/cursors, stale reads/admission, deferred/unknown publication, released retries, conflicting local requests and exact REST bodies. Simulator flows cover inspection, selection, review and retained metadata on phone, iPad and maximum text. No personal records, live Pod mutation or release version change.
