# Alarm context and curve recovery

October 26, 2026. Implementation and local rendered validation complete; CI and merge follow. No live alarm, temperature or run-once mutation has been sent.

The web's temperature context follows its single active sleeper (`src/lib/singleSleeper.ts`, `TempScreen.tsx`), falling back to the selected side when zero or two sleepers are active. Native alarm/room/recent-sleep context now uses the same rule in Dial, Slider, Night & Dawn and Stage. The Both sides view preserves both thermal controls while showing the configured active sleeper's context. The next thermal-window label uses the Pod timezone.

A failed alarm refresh leaves cached rows explicitly stale and disables editing/testing. Next alarm no longer presents an unverified occurrence. Uncertain alarm writes require a fresh read before resubmission. Vibration Stop remains available independently.

Curve library refresh commits its library and both run-once sessions together after every read succeeds. A failed read cannot combine new left-side status with stale right-side status. Uncertain starts/cancellations and failed follow-up reads block further changes until a successful refresh; readback never replays a mutation. Cached curves remain visible but disabled.

The native curve menu also opens the existing AI JSON import directly. Import, library review and Run once review retain explicit confirmation; Demo can exercise these routes without hardware. An older controller's save-by-name curve library retains its selected-day Apply confirmation. Screenshot review caught the old AI preview sorting its chart by clock string and assigning morning points to warm-up. The preview now uses the same overnight ordering/chart as the saved payload; labels describe Start/Cooling/Warming/Hold, not predicted sleep stages. The editable point list uses the same order, and its recurring clock picker uses a fixed UTC date to preserve times across DST.
