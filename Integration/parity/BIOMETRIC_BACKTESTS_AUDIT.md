The draft accepts at most 60 inspected sessions from the chosen side and 20 compatible reference revisions, one per family. Changing the sleeper clears reference selections. A separate review displays the exact sessions and reference hashes before freezing.

The REST create body omits controller timezone and preserves the sorted selection and one random retry key in protected controller/side-scoped storage before sending. Reopening never writes. Explicit retry retains the same key; the server's timezone can independently cause a request conflict. A released idempotent response stays released. Creation does not run an evaluation or apply a profile. Competing local workspaces cannot replace a different pending intent or retry one already removed elsewhere.

## Numeric/reference trace and activation authority inspection

Also read numeric-trace-page.ts, reference-trace-page.ts, promotion-build.ts, profiles/activation.ts, qualification-registry.ts and evaluation-store.ts. Numeric trace rows retain configHash, side/sourceSide, nullable HR/breathing/index/quality, HRV metric, nullable flags and limitations. Provenance is retained_waveform_recomputation; original timestamps remain before reference clock offset. The backend returns only the dataset side within evaluated windows, requires one exact matching output, and caps output at 500 rows per page.

Reference trace requests omit configuration and require cohort+metric; the descriptor binds job/report/dataset hashes, side, cohort, metric, offset, frozen offset/tolerance and source-time provenance. Frozen reference rows omit submitted original payload/annotations/subject, include import UUID/revision/hash/source and nullable compatibility exclusion, and never use the current mutable source library. The backend only includes points/intervals fully inside evaluated windows; unknown HRV families can be returned as excluded comparisons. No scores are recomputed by these page reads.

Validated activation review is point-in-time and returns eligible:true only after verification. Applying repeats verification under short reservations, with exact side/revision/hash/generation/evaluation/report and a durable idempotency key. The server owns installed evaluator/Python build identity and policy qualifications; no RPC can create the bounded installed promotion registry. A matching registered protocol/build/manifest and qualified stage policy are required, with waveform context for signal replay. Missing/ambiguous/malformed registry means unqualified. The app must never derive eligibility from a report's improved label.

Verification requires the exact retained report and dataset, compatible candidate, desired/runtime baseline agreement, appropriate opposite-side runtime for waveform replay, current generation, and unchanged job/result fencing and hashes. It rechecks succeeded status, unreleased bytes and holdout use exactly once before committing. A prior identical activation is returned before probing current artifacts/build. Detailed evaluation-assessment policy checks and report views still need implementation/audit before the validated activation UI is added.

## Waveform selection audit completion

Read raw-catalog.ts in full, waveform-contracts.ts, waveform-selection.ts, waveform-dataset.ts, admission-service.ts, WaveformDatasetBuilder and ReplayResources. Raw pages use a half-open requested window but inclusive archive event bounds; overlap is potential, not continuous coverage. Source IDs bind source filename + artifact hash + inventory version. Replaced filenames invalidate old catalog identities but do not modify retained bytes. Source inspection is explicitly `retained:false`; `requires_reverification` does not mean replay-ready. The inventory has record totals, timestamp errors/reversals/duplicates, channel samples/lost markers/truncated bytes, event bounds and ordered availability. Expose these as recorded inspection facts.

Freeze request is only parent UUID/hash, every cohort ID with 1–64 distinct source hashes and an idempotency key (maximum 60 cohorts, identifiers bounded). The server sorts IDs for retry identity and can return an existing descriptor before rechecking the mutable catalog. It derives historical occupancy from retained presence/absence intervals only: unrecorded or conflicting intervals remain unknown, the other side and sleeper mode remain unknown, and pump context is not guessed. It requires ordered nonoverlapping distinct artifacts, verifies/copies bytes, and enforces per-dataset source/byte bounds. It cannot transform a waveform dataset into another waveform parent.

The web offers explicit next-archive scan, restart local cursor, one-night selection with per-night clearing, paged source inspection, whole-selection retention and deferred/released status. Retention is allowed to request deferred work even when admission is unavailable; inspection needs a fresh admitted decision. An explicit retry must preserve the exact old key and parent/selection, including after app restart, rather than create a new plan because admission changed. ReplayResources distinguishes Python process measurements from sampled coordinator/worker RSS and admission-time ingestion observations; neither establishes continuous live health.
