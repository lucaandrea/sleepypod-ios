# Native retained evaluation reports

2026-10-26. Audited Core's BacktestReport, NumericReport, StageReport, StageTrace, NumericTrace, ReferenceOverlay, ObjectiveThresholds and ReplayResources views and their REST contracts. Validated profile activation is a separate remaining portion.

The native report screen preserves the distinction between no committed report, released details, an incompatible report and a failed read. The immutable job, dataset, evaluation scope, side, configuration hashes and complete-report hash bind every accepted response. Summary, numerical and stage projections are parsed independently. An older poll cannot reinstate released scores, and a failed refresh preserves the previous report while removing the release action until a successful read.

Numerical comparisons include per-night errors, reference/output coverage, unmatched counts, exclusions, shared-timestamp versus own-support comparisons, lost/added/ambiguous readings, pooled versus equal-night scores, exploratory uncertainty and all reference-defined subgroups. Stage views include equal-night and pooled scores, per-night coverage, all sixteen confusion durations and per-stage precision, recall and F1. Nested frozen policy thresholds and available processing/health observations retain their scope and limitations. Missing measurements remain unavailable.

Stage charts render exact intervals with gaps. Numerical charts plot individual readings without interpolation. Night/configuration selection resets the page; identity checks and read generations prevent delayed responses from replacing a new selection. Frozen reference overlays retain independent pagination, add the frozen clock offset only to recomputed timestamps, and plot compatible point/interval records in a distinct color and shape. The view does not create extra pairs or scores. Exact rows expose source times, hashes, quality, flags and unavailable fields. Charts and native rows respect the Pod timezone and chosen clock format. Plot heights and axis annotations are bounded at accessibility sizes; all exact data rows keep the full chosen text size. Wrapping native menu labels avoid clipped metric/configuration names.

Report release requires explicit confirmation, retains the exact job/hash request in the existing protected controller/side recovery store, and reads the summary before any retry. A nullable response is not success. A confirmed prior release clears the request without repeating the mutation; a changed hash or missing summary remains unresolved. Reopening does not send writes. The audit hash remains after detailed scores and traces are released.

Demo uses literal Core-evaluated synthetic examples from the checked-in generator. It does not assign their scores to a newly queued candidate, simulate a worker, manufacture validation evidence or adopt a profile. All trace pages are generated by Core's own pagination functions. A separate literal three-metric fixture covers all 36 subgroup rows (four groups × three configuration comparisons × three metrics), while rejecting an over-limit 37th row. It was generated against a read-only source snapshot of Core commit `4673112c6c6355452a553b798177f6593bb29abf`; no Core checkout was edited. The corresponding Core PR #32 is merged at `8572ba10f845a9636b21e0aca21efbf5e8c31ce1`. Their hashes describe complete synthetic reports, not personal records.
