# Personal-account reports

Mode: Read for the report; Operate for model settings and request review.
This extends the existing morning brief, Health enrollment and web-copy screens.
It retains native navigation, Theme, system Form, Dynamic Type and the rendered
report components. No new visual identity or replacement design system is needed.

## Task and hierarchy

Each authenticated sleeper reads their own report and chooses their own model.
The latest saved brief leads. An empty account explains how to connect its own
Health history. Model settings and Health history are adjacent, explicit links.
Creating a report starts with a question, followed by a review of the selected
source, calculated evidence and destination. Off-device consent starts off for
each request. The full report and provenance remain expandable.

Follow-up answers retain the original report's evidence. Sharing a copy with the
Pod is a separate choice, with private-account visibility and withdrawal stated
at that action. Model credentials never appear in report content or web copies.
Apple's local model is the default; supported cloud and local-server providers
are explicit alternatives. A provider model listing does not prove access.

## Boundaries and states

Preserve account-specific encrypted reading during an outage. Creating, testing
or sharing requires the current personal session. Backgrounding, locking,
revocation and account changes withdraw active access and discard late replies.
Unusable storage is preserved rather than replaced. Model failure has a local
explanation and no automatic retry. A consented cloud request already dispatched
cannot be recalled, and its cancellation must not promise otherwise.

The user approved the complete two-person experience and richer morning brief
in workstreams 12 and 16. These screens do not enable temperature adaptation or
change alarms, arrangements or physical controls. Missing data is unknown.

Verify empty, saved, model-settings, evidence review, consent, completed report,
follow-up, web sharing, unavailable storage, offline and cancelled/error states.
Use both iPhone and iPad, light and dark appearances, largest Dynamic Type and
native navigation. Synthetic examples label themselves and cannot reach Health,
Keychain, providers or hardware. Capture the real simulator rendering and pass
it to an independent finish reviewer; no HTML/CSS detector applies.
